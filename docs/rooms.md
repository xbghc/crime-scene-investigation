# 房间系统

网页版继续保留。输入原来的访问密码后，可以创建房间或输入六位房间码加入；房间内可复制邀请码或邀请链接。每间房独立保存玩家、牌堆、角色、答案和对局状态，支持 4–10 人。只有房主可以开始或重置，所有在席玩家必须在线才能开始。

## 离开与重连

- 房间码不区分大小写，不包含易混淆的 `I`、`O`、`0`、`1`。房间码是邀请入口，不是玩家身份凭证。
- 浏览器保留原有登录 token 和最近房间码。刷新、断线重连会用同一身份恢复原房间、角色和当前阶段；重新登录、清理浏览器数据或换设备不会恢复旧身份。
- 同一身份仅能属于一个房间；进入其他房间前必须退出当前房间。相同身份在另一个标签页连接时，新页面接管，旧页面离开广播组且不能再操作或获取房间状态。
- 等待大厅中断线席位保留 2 分钟。清理任务每 30 秒运行，实际释放可能稍晚。原房主离线满 30 秒后自动转交给在线玩家；无人在线时，下一位重连玩家可接任。房主重连后不会夺回已经转移的权限。
- 大厅及结算阶段可以退出；房主主动退出立即转移房主，最后一人退出删除房间。游戏中不允许主动退出或换房，以免破坏已分配的角色；可等待本局结束，或请房主重置后退出。
- 进行中的对局不会因单个玩家断线而踢人或重新分配身份。所有玩家离线连续一小时，整间房才会被清理。

## 运行边界

房间与游戏状态仅保存在当前服务进程内存中。重启会丢失房间和未结束的对局，客户端恢复失败后返回创建/加入入口。此版本使用 Socket.IO 默认内存 adapter，必须部署为单进程实例；不能直接开多实例或多 worker，需要共享存储与分布式房间协调后才能横向扩展。

最多同时保留 100 个房间。生命周期常量位于 `server/src/engine/GameEngine.ts`（`HOST_TRANSFER_DELAY_MS`）、`server/src/types.ts`（`RECONNECT_TIMEOUT_MS`）和 `server/src/rooms/RoomManager.ts`（`ROOM_IDLE_TIMEOUT_MS`、`MAX_ROOMS`）。生产环境仍需设置安全的 `JWT_SECRET` 和 `GAME_PASSWORD`，避免使用原项目开发默认值。

## 协议与隔离

- `create_room { nickname }`、`join_room { code, nickname }`、`resume_room { code? }`、`leave_room` 使用可选确认回调 `{ ok, error?, code? }`。
- 不带房间码的恢复请求按当前登录身份查找服务器已接受的成员关系，支持创建/加入成功但响应丢失后的恢复。无成员关系时返回 `{ ok: true }`。
- 成功加入时先发送 `room_state`（包括 `code`、`minPlayers`、`maxPlayers`、成员 `connected`），进行中另发送该身份专属 `full_state`，最后返回确认。
- `room_left`、`room_closed` 清除本地房间与私密对局状态；`session_replaced` 使旧标签页停止自动连接。
- 所有游戏操作和 `request_state` 都检查服务端身份归属及当前 socket 所有权，不能通过请求参数选择别人的房间或玩家身份。
- 广播均发送到当前房间。私密状态额外检查目标 socket 身份和房间；侦探在结算前不能获得凶手答案或隐藏身份。

## 验证

```sh
pnpm --filter client build
pnpm --filter client test
pnpm --filter server exec vitest run
pnpm --filter server exec tsc --noEmit
pnpm lint
pnpm format:check
```

服务端包含真实 Socket.IO 连接集成测试：双房间与旁观连接隔离、私密答案、错误房间码、满员、重连、重复连接接管、退出/房主转移、跨房间操作、失效房间和重置时取消旧定时器。引擎测试覆盖离线死亡状态、30 秒房主宽限、角色级私密快照和结算后离开。客户端测试覆盖服务端确认、失败/超时、重连及清理上局私密数据。
