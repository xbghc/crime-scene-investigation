## 已复现问题1：停电中刷新，目击者无法换板

复现：四人正常开局 → 指证完成 → 第一轮讨论结束 → E07停电 → 目击者刷新。

观察：身份、推进阶段和1张待换新板恢复，但可替换旧板数为0；预期有5张非死因旧板供目击者完成操作。截图显示“当前场景板”为空、新板仍显示且确认替换按钮无法启用。

依据：需求文档第153行及第215–216行要求目击者选择旧板并用新板替换。GameEngine.ts:1122在停电快照中对目击者也返回空boards；AdvancePhaseView.vue:154–180必须先选旧板。

这不是要求侦探绕过停电影响，而是目击者必须保有完成本阶段的操作信息。产品修复尚未授权，本PR不修改业务逻辑。

## 已复现问题2：帮凶未选择，目击者却可点击继续

复现：六人正常开局 → 第一轮讨论结束 → 帮凶停留在“更换线索牌/不更换”的选择界面。

观察：另一浏览器中的目击者同时看到“推进阶段完成，没有新的场景板”和可启用的“继续”；可启用控件数为1，预期为0。此条浏览器断言直接验证了错误操作入口；没有把它夸大为已点击并验证所有后果。

依据：需求文档第144–154行明确先帮凶抉择，再按选择抽1或2张板，最后由目击者替换。前端将newBoards为空误当完成；handlers.ts:120–126也未校验帮凶决定状态。这项后端后果是源码分析，不是本条UI断言已经证明的全部行为。

## 边缘测试扩展

新的边缘用例由playwright.edges.config.mjs单独运行，使用原始服务器入口，与经典组/房间组串行执行，避免端口冲突。UI流程与浏览器内恶意协议请求分开命名；后者用于验证服务端权限，不能冒充普通用户UI覆盖。

本文件上面的9条是已完成基线。边缘新增用例的实际通过/失败数量以本PR最新CI的edges-summary.json及日志为准；发现和语法检查不等于浏览器通过。

本次新增7条（合计16条）：
- 容量边界：1–3人禁止开始、4人允许、10人开局、第11人拒绝。
- 连续点击创建/加入/开始：被动观察事件，要求只创建/加入一次、只收到一次game_started。
- 同身份第二标签接管：身份/座位不变，旧标签被锁定且清空私密状态。此条是UI接管隔离，不宣称已发送断开的旧socket攻击。
- 房主关闭页面后在真实30秒宽限期内重开：恢复身份/房主/座位，越过原截止时间仍不错误转移。
- 连续确认破案：失败结果只广播一次，只消耗本人权利，另一侦探仍可正常获胜。
- 六人在夜晚/部分指证/讨论刷新：身份、牌、标记和各自秘密恢复，侦探始终不获得答案。
- 明确标为“协议攻击（浏览器）”：伪造跨房间代码、目击者身份被服务端拒绝，两房状态不变，随后正常UI仍能完成游戏。

所有断言正常运行；没有test.skip、test.fail或修改生产代码来隐藏问题。最新CI会串行运行经典6条、房间3条、边缘7条，记录每组真实结果。
