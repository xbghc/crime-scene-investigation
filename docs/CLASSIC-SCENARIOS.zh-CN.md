# 犯罪现场：经典多人路径测试脚本（待审阅）

## 先看结论

这是一份可运行的测试草稿，不是“所有测试已通过”的报告。已准备 **4 场经典游戏、2 条中断/越权回归、3 条房间与重连测试**。语法、测试发现、测试服务器类型检查和启动检查已通过；当前云执行环境禁止 Chromium 所需的 Unix socket，尚未执行浏览器中的点击和整局验证。未提交、未创建 PR、未运行远程 CI。

测试依据当前仓库 GameEngine、Socket.IO handlers 和 Vue 界面。下文“应当”是断言要求，“源码现状”是已读代码的行为；两者不一致处单独标注，不能当作已经浏览器复现的缺陷。

## 测试怎样控制，哪些地方不控制

- 每名玩家一个独立浏览器上下文，隔离 localStorage 和登录身份，模拟 390×844 手机视口。
- 登录、创建/加入房间、选牌、目击者放标记、换板、破案、重开全部通过真实 UI；不直接发 socket 游戏事件，不直接改前端状态，不调用强制结束方法。
- 身份、手牌仍由真实引擎随机分配。脚本只在读到各浏览器实际收到的身份后分派操作，不固定“玩家1必为凶手”。选对或选错的答案由测试协调器安排；这不向侦探浏览器注入答案。
- 4 人是“1目击者＋1凶手＋2侦探”；6 人是“1目击者＋1凶手＋1帮凶＋3侦探”。
- 为稳定覆盖效果牌，经典组使用独立 `server/e2e/scenario-server.ts`：仅在 `NODE_ENV=test` 启动，绑定 `127.0.0.1:8040`，复用真实认证、房间管理和事件处理。正常开局后，用引擎已有测试方法设置两张 E07“停电”。无测试管理 HTTP 接口、无生产入口改动。
- **E07 连续两张是人工测试牌堆，生产牌堆不会自然重复这张牌。** 这是覆盖两次推进分支的受控测试，不宣称它是完整生产随机牌堆的抽样。
- 登录 PIN 是测试用固定值，JWT 签名密钥在经典测试启动时随机生成；不使用任何真实玩家账户、生产密钥或保存的浏览器凭据。

## 共同开局

四人或六人依次登录、创建/加入同一房间 → 房主开始 → 正常等待约3秒身份阶段 → 凶手选择自己第一张手段与第一张线索 → 目击者确认 → 六张场景板各选一个选项并确认 → 第一轮讨论。

共同隐私断言：在结束前，侦探浏览器没有 `murdererSelection`，玩家列表不泄露凶手/帮凶身份，也没有只发给目击者的新场景板。断言读取的是各自收到的前端状态，不是服务器完整秘密。

### 经典01：一击破案

- 人数：4。
- 行动：侦探A选择真正凶手、所选手段、所选线索，确认破案。
- 预期：全员进入 `game-over`，显示“侦探方获胜”，公开四人的身份与答案。
- 分数：目击者6，两个侦探各5，凶手0。
- 结束条件：四个浏览器的胜方和每个玩家得分一致；任何客户端仍留在讨论、身份未公开或分数不符均失败。

### 经典02：误判不团灭，另一名侦探补救

- 人数：4。
- 行动：侦探A指认真凶，但选凶手手中另一张错误手段；错误提示后，侦探B用正确组合破案。
- 第一次预期：A失去一次性破案权，“破案”按钮消失并显示“已用破案权”；A不会因此死亡；全员仍在第一轮讨论；其他玩家仍可行动。
- 最终预期：B正确破案后侦探方胜，分数与经典01相同。A虽误判，仍按阵营获胜得到5分。
- 失败条件：误判直接结束游戏、A可再次破案、B也失去破案权、或误判者被错误扣除阵营获胜分。

### 经典03：三轮无解，强制破案全错

- 人数：4；前两轮不主动破案。
- 行动：目击者结束讨论1 → 推进1抽E07、替换1张非死因板 → 讨论2 → 推进2抽E07、再替换1张 → 讨论3 → 强制破案。
- E07断言使用**当前实现**：推进时 `blackout=true`、全员看到停电效果弹窗；进入紧接着的讨论2/3时 `blackout=false`。这不是牌面规则已正确实现的证明，见下方风险。
- 强制阶段：只允许当前轮到的人看到“开始破案”；按加入顺序，仍存活、有破案权的3名非目击者（含凶手）各错一次。脚本选择真凶持有但未用于作案的另一张手段，确保合法但错误。
- 预期：恰好3次失败，轮次不重复、不跳过，最后凶手方胜；凶手3分，其余0分。
- 失败条件：提前强制破案、目击者入队、非当前玩家可操作、失败后不换人、或次数用完仍不结束。

### 经典04：帮凶换线索，旧答案失效

- 人数：6。
- 行动：第一轮结束后，帮凶选择凶手手里另一张线索并确认；目击者收到新答案与2张新场景板，实际替换两张后继续。第二轮，侦探A用旧答案尝试；随后侦探B改用新线索。
- 中间预期：手段不变，答案只更新线索；侦探端仍无私密答案；新板只发给目击者；旧答案失败仅消耗A的破案权。
- 最终预期：新答案成功，全员侦探方胜；目击者4分，三个侦探各3分，凶手/帮凶0分。
- 失败条件：旧答案仍成功、帮凶替换未同步给目击者、只给1张板、第二张板无法替换，或侦探提前看到秘密。

## 两条明确保留的回归断言

这两条针对源码审查发现的风险，**不跳过、不写成“预期失败即成功”**。如果运行后失败，应保留截图和trace，由结果判断是产品问题还是脚本问题。

### 回归05：停电时目击者刷新

四人进入推进1、停电生效后，目击者真实刷新页面。预期恢复当前房间、当前阶段和1张待替换新板，同时仍有5张可替换的非死因旧板控件，能够继续游戏。

源码风险：停电的完整快照对所有角色都返回空 `boards`；目击者也可能失去旧板列表，导致无法选旧板、无法换新板。此条目前止于“5个可操作旧板控件恢复”的关键断言，不宣称已经完成后续整局。

### 回归06：不能跳过帮凶决策

六人进入推进1，帮凶尚未选择时，目击者不应有可点击的“继续”结束推进。预期隐藏或禁用该控件。

源码风险：前端把 `newBoards=[]` 解释为推进已完成，而等待帮凶时也正好为空；后端结束推进目前没有检查帮凶是否已选择。此条检验 UI 门禁，不把 UI 门禁视为完整服务器权限证明。

## 另外3条房间/连接测试

`e2e/multiplayer-ui.spec.mjs` 仍使用原始生产服务器入口与随机牌堆：

1. 格式错误房间码、已清空且不存在的有效房间码；两个独立大厅；房主主动退出后的转移；退出再加入；刷新不生成重复成员；非房主不可开始。
2. 四人完整正确破案＋破案向导取消/返回修改＋侦探刷新重连＋房主再来一局。
3. 两个房间各4人、共8个隔离上下文：A开局时B仍在大厅，随后B开局；两房成员、阶段和房间码不串。

## 需要先确认的产品规则/风险

- E07牌面写“隐藏一轮，下一轮发言结束后恢复”，引擎却在**下一轮开始**时恢复。经典03记录实现现状；建议决定最终应以哪个规则为准，再添加严格的视觉隐藏时长断言。
- 正常推进界面没有把 blackout 传给旧板展示，停电时可能仍看得到板；但刷新后快照又可能完全清空板。这两种路径不一致，尚未浏览器验证。
- 目击者取消已选标记时，前端发 `optionIndex=-1`，后端拒绝负数。本组经典开局每板只选一次，因此不声称覆盖取消标记。
- 本组不覆盖所有10张效果牌、长期掉线房主转移、最大人数/压力、设备兼容性或网络延迟。效果需要人工/目击者交互的分支不能仅凭这组脚本判定完成。

## 运行与验收

把压缩包内文件按相对路径放进对应版本的仓库，先查看差异，不覆盖业务源码。需 Node22、仓库锁定的pnpm和可运行浏览器的Linux环境。

```sh
pnpm install --frozen-lockfile
node node_modules/playwright/cli.js install --with-deps chromium
# 仅检查9条用例能被发现，不启动浏览器：
node node_modules/playwright/cli.js test --config=playwright.classic.config.mjs --list
node node_modules/playwright/cli.js test --config=playwright.multiplayer.config.mjs --list
# 实际运行，两个配置串行执行，避免8030/8040端口冲突：
node node_modules/playwright/cli.js test --config=playwright.classic.config.mjs
node node_modules/playwright/cli.js test --config=playwright.multiplayer.config.mjs
```

每个用例有明确超时，无无限等待循环。失败不会自动修改游戏代码。每位玩家保留截图、trace、page error、console error与网络错误；输出在 `test-results/` 和 `playwright-report/`，不提交Git。trace只包含本次虚拟测试玩家的数据，仍建议仅仓库协作者可见。

当前验证：9条测试可发现；脚本语法/格式通过；独立测试服务器 TypeScript 与 ESLint 通过；服务器健康检查及测试登录返回200。**浏览器启动仍被当前平台限制，不能将这些静态/启动检查写成整局通过。**
